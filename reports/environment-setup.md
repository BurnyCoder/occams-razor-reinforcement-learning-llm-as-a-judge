# Environment setup record

The running judge reports reference PyTorch fallbacks for Gated DeltaNet because optional FLA kernels are absent. The next runtime adds the pinned MIT-licensed `fla-core` package, which supplies the Triton operators used by the existing Transformers implementation without a CUDA compiler. Torch and Triton are already pinned through the training environment. The separate causal-convolution fallback remains documented until measured profiling shows a need to replace it. Sources: [official FLA installation guide](https://github.com/fla-org/flash-linear-attention/blob/main/INSTALL.md), [license](https://github.com/fla-org/flash-linear-attention/blob/main/LICENSE), [pinned Qwen implementation](https://github.com/huggingface/transformers/blob/v5.17.0/src/transformers/models/qwen3_5/modeling_qwen3_5.py). This dependency is not installed into the active audit process; that run retains its original runtime.

The Hugging Face model-search connector returned an unavailable-tool error, so the official Hub metadata API and model card were used to freeze the next candidate judge revision. Downloading the candidate does not qualify it or authorize using it for rewards before the fresh audit and GPU checks.

The pinned Transformers tokenizer now defaults `apply_chat_template` to `return_dict=True`. Direct source inspection found that the data-budget check expected a list and generation expected a tensor. Both calls now explicitly request `return_dict=False`; otherwise counting dictionary keys would undercount prompts and `BatchEncoding.shape` would fail. This API correction precedes frozen data and all policy outputs. Source: [Transformers tokenizer API](https://huggingface.co/docs/transformers/v5.17.0/en/main_classes/tokenizer#transformers.PreTrainedTokenizerBase.apply_chat_template).

The already-started judge process subsequently reproduced that `BatchEncoding.shape` failure after loading its weights on CUDA, before generating a judgment. Its memory observation is retained in the operation log; it establishes weight-loading fit only, not inference fit or judge qualification. The retry uses the published explicit return-type correction. The relevant data/verifier regression suite now passes; both pre-fix failures and post-fix checks are saved under `results/tests/quantity-*.xml`.

A read-only Python stack sample located the data-startup delay in Transformers' eager `importlib.metadata.packages_distributions()` call. A syscall sample confirmed repeated checks of Torch header files. [Upstream already fixes this](https://github.com/huggingface/transformers/blob/41f9d3992023970fb5a463e70d56232506c80fbc/src/transformers/utils/import_utils.py) with lazy mapping and direct version lookup first. The project backports only that logic, keeping the compatible library version and Apache license, checking the exact original bytes and recording patched hashes. The uv cache is not edited. This is a runtime compatibility patch, not a reward, data or model-method change.
