# Amendment: explicit ratings, constrained JSON, and exploratory training

2026-11-17. This amendment precedes any policy training. It follows the completed larger-judge audit, retained in [its immutable artifact](../results/judge-audits/qwen-2026-11-17T03-00-23.431+00-00.json). Counts are generated in [readiness](readiness.md). The earlier rubric frequently produced count-like ratings despite positive rationales, malformed `rationle` keys, and confusion between unnecessary content and missing reasoning. Model capacity alone did not resolve this configuration's failures. Because audits differ, this is not a paired capacity ablation.

The revised prompt explicitly makes every dimension a quality rating with the same direction; zero unnecessary assumptions earns the highest assumption-economy rating. It separates reasoning sufficiency from redundancy, requests short evidence before ratings, and shows valid JSON. The meanings, ordinal range, equal weighting, correctness gate, policy configuration and pass thresholds remain unchanged. The next attempt uses [fresh constructed cases](../configs/judge-audit-v3.json), frozen before its first response. These checks remain small, deliberately obvious specification tests, not independent human preference validation.

Qwen decoding now uses [LM Format Enforcer](https://github.com/noamgat/lm-format-enforcer/tree/817f944fcc8851917c40300a47f62d1defc3ffc3), an MIT-licensed existing implementation, through its public Transformers prefix-token API. The release on PyPI imports a tokenizer module removed in Transformers 5; the pinned upstream commit includes the compatibility correction. The same validated judgment schema supplies the grammar, with explicit score enums because this parser does not enforce numeric bounds. No raw output is repaired after generation. Pydantic still rejects contradictions, and invalid judgments still earn no bonus. Grammar prevents some syntax errors; it cannot establish semantic reliability.

The user subsequently authorized trying training despite residual judge intelligence/noise failures. Accordingly, `allow_unqualified_training_judge` permits exploratory training after a completed audit of the **current** Qwen model, revision, prompt and audit. It neither changes `passed` nor permits a stale or absent audit. The waiver applies only to the training judge. GPU headroom, verifier correctness, data publication, checkpoint checks and independent Gemma qualification remain required. Reports label the entire waived comparison exploratory. This is a declared departure from the original qualification prerequisite, not a retroactive success claim.

After this bounded correction and audit, proceed to GPU profiling and the Occam pilot even if the quality threshold still fails. Inspect actual reward spread, invalid judgments and parameter updates before selecting the retained-run budget. Do not enter an open-ended judge-prompt tuning loop. The Occam-first and publication-before-execution ordering remains unchanged.

## Existing implementations checked

- [ConciseRL's reward server](https://github.com/RazvanDu/ConciseRL/blob/0807d2f75b22423fbf130ca9a776ced4f35139e7/reward_server/math_server.py) separates answer verification from judged conciseness and explicitly discourages answer-only traces. Its launch script uses multiple GPUs, Ray/OpenRLHF and a hosted judge, so wholesale execution does not meet this project's local laptop constraint. Its malformed-score fallback can exceed its nominal normalized range; we retain strict validation instead. The repository is Apache-2.0 licensed. We inspected its implementation; we did not copy its service or claim a replication.
- [TRL's custom rollout interface](https://huggingface.co/docs/trl/grpo_trainer) already supplies the GRPO loss, optimizer, reference handling and checkpoint machinery. Keep using that implementation instead of copying an older PPO trainer. Compare any concrete runtime incompatibility against the installed pinned source before adding custom patches.
- [Unsloth's Qwen3.5 guide](https://unsloth.ai/docs/models/qwen3.5/fine-tune) supplies the local BF16 LoRA path. Actual backward/generation compatibility still needs to be measured on this machine.
- [G-Eval](https://www.microsoft.com/en-us/research/wp-content/uploads/2023/03/2303.16634.pdf), read through its appendices, motivates separating criteria, evaluation steps and structured scoring. Its evidence concerns other models/tasks. This project does not implement its generated evaluation steps or probability-weighted scoring and does not infer that its reported gains transfer here.

Regression specifications were published before the structured-decoder helper existed; the recorded collection failure is in [the test artifact](../results/tests/structured-before.xml). Follow-up tests check the observed key typo, illegal ratings, semantic contradictions, and the training-only waiver's identity checks.
