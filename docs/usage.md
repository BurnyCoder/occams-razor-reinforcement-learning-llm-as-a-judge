# Installation and execution

Use an Ubuntu WSL shell in the cloned repository. All commands below assume published source, Python 3.12, `uv`, a working NVIDIA CUDA driver and Docker. Never run model commands with a dirty or unpushed checkout. The CLI and pytest session enforce the Git publication gate.

```bash
# Authoring/setup only; the lockfile is already committed.
bash scripts/setup_wsl.sh
# Authenticate only if the machine does not already have access.
hf auth whoami
gh auth status
```

`.env.example` contains paths, not credentials. `.env` is ignored. Keep model caches, run outputs and checkpoints on D: to avoid filling the system drive. The local venv remains in this checkout. Do not enable hosted inference services. The compatible dependency set is in `uv.lock`; upstream Unsloth version bounds intentionally constrain Torch, Transformers and TRL.

## Publish checkpoints between phases

The setup script includes the standard user `uv` install directory in PATH for noninteractive WSL shells. It uses `UV_LINK_MODE=symlink` so the project-local venv links packages from the D: cache instead of duplicating large CUDA libraries on C:. Keep that cache available; deleting it would break those links.

Every phase may create publishable manifests, reports or README changes. Before running the next phase, review the files, commit and push them and verify the remote SHA. `occam publish --source` mirrors the current source snapshot to the single Hugging Face collection; retained training and pilots require that receipt for the exact current Git commit. `git add` should name intended files; never include `.env`, caches or raw weights.

```bash
git add README.md docs reports manifests configs src tests uv.lock site paper
git commit -m 'Describe the concrete change'
git push
git rev-parse HEAD
git ls-remote origin "refs/heads/$(git branch --show-current)"
uv run --frozen occam publish --source
```

Use meaningful feature branches and merged pull requests. The commands above show the recurring publication step; do not mechanically create empty commits.

## Readiness

```bash
uv run --frozen pytest -m 'not sandbox'
uv run --frozen pytest -m sandbox
uv run --frozen occam resolve
# Publish the resolved revisions, then build the pinned CUDA llama.cpp runtime.
bash scripts/build_llama.sh
# If nvcc is unavailable, install the checksum-pinned official CUDA binary instead:
uv run --frozen python scripts/install_llama.py
# Set OCCAM_LLAMA_SERVER in ignored .env to the printed path.
uv run --frozen occam doctor
# Publish runtime manifest before the next phase.
uv run --frozen occam prepare
# Publish generated split IDs and hashes before any training.
uv run --frozen occam qualify qwen
# Publish the audit; a failed judge cannot provide training rewards.
uv run --frozen occam profile
uv run --frozen occam select-gemma
uv run --frozen occam qualify gemma
```

Publish changes between commands whenever the working tree changes. Qualification and GPU profiling are prerequisites, not standalone baseline runs. No training data are generated by a hosted model. The procedural-only flag is for exploratory debugging, not a replacement for the registered public comparison. An unsupported public answer type is excluded before policy performance is observed and reported in the exclusion log.

## Occam first

```bash
uv run --frozen occam train occam --seed 17 --pilot
uv run --frozen occam budget
# Publish frozen update budget and source receipt before retained training.
uv run --frozen occam train occam --seed 17
# After interruption, keep the same configuration and data:
uv run --frozen occam train occam --seed 17 --resume
uv run --frozen occam report
# Publish generated paper/reports/README/site, then upload the completed run.
uv run --frozen occam publish --run occam-seed17
# Publish first-occam.json before baseline execution.
```

Full state is saved at optimizer boundaries, periodically and on a clean signal. An abrupt restart resumes from the latest completed checkpoint; any work since it is repeated. Preserve raw logs, including repeated attempts, rather than treating them as independent evaluation samples. Resume checks reject changed scientific configuration. The first pilot is excluded from retained comparisons.

## Prompt-only and trained baselines

```bash
uv run --frozen occam evaluate prompt_ordinary --split calibration --seed 17
uv run --frozen occam calibrate
# Publish normalizers before any length training.
uv run --frozen occam evaluate prompt_ordinary --seed 17
uv run --frozen occam evaluate prompt_concise --seed 17
uv run --frozen occam evaluate prompt_occam --seed 17
uv run --frozen occam evaluate occam --seed 17
uv run --frozen occam train accuracy --seed 17
uv run --frozen occam train token --seed 17
uv run --frozen occam train formal --seed 17
```

After **each** trained model and each evaluation, regenerate/publish reports and upload that run before proceeding. Subsequent seeds follow the same order with Occam first; shuffled simplicity is the last trained control. `--limit-per-domain` produces clearly labeled exploratory evaluations. All arms use the same task IDs, generation settings, maximum completion, full-trace counting and independent evaluator. Prompt-only baselines use unchanged original-model weights; their instructions differ.

## Monitoring and reporting

```bash
uv run --frozen occam dashboard --port 8765
# Open http://127.0.0.1:8765/?live=1
uv run --frozen occam report
```

The live view polls saved events and labels training accuracy as training accuracy. Static GitHub Pages uses generated `site/data.json`, with no remote model computation. The report command creates every measured table, plot, example list, aggregate report, per-run report, Markdown paper and PDF. Investigator notes belong in each run's `notes.md`; include what failed, why a fix was chosen, and whether an analysis was planned or post hoc. Inspect the rendered PDF before publication. No fabricated benchmark scores, sample outputs, uncertainty bars or training curves are included.
